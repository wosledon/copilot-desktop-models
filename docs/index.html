Copilot Desktop canvas

Bring any model to Copilot.

Browse models.dev, pick a provider and its chat models, and add them to Copilot Desktop's Other Providers with reasoning effort levels and credentials in the OS credential store.

What it does

Writes the real registry

Providers and models go into ~/.copilot/data.db (model_providers, provider_models), the same store the Other Providers settings use.

Works in every session

Because the rows live in Copilot Desktop's own database, a new session sees the provider without editing any file or restarting the app.

Reasoning effort

Levels are written to supported_reasoning_efforts, which is what makes Copilot's reasoning-effort control appear for a model.

Secrets stay secret

API keys and bearer tokens go to the OS credential store under byok:<id>:apiKey. The canvas and the agent never receive them.

Catalog mapping

Token limits, vision support, and reasoning options come from models.dev, together with model names and identities.

Edit and remove

Existing app providers can be edited or deleted from the canvas, including their model list and effort levels.

Install

Requirements: GitHub Copilot Desktop with canvas support, and network access to models.dev.

git clone https://github.com/wosledon/copilot-desktop-models
cd copilot-desktop-models
npm run install:extension

The command copies the extension to ~/.copilot/extensions/models-dev-providers ($COPILOT_HOME when set). Start a new Copilot session, then open Canvases → Models.dev Providers.
